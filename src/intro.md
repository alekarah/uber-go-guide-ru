# Введение

Стиль — это соглашение, которое определяет, как мы пишем код. Сам термин «стиль» не совсем точен, поскольку эти соглашения охватывают гораздо больше, чем просто форматирование исходных файлов — этим за нас занимается `gofmt`.

Цель данного руководства — разобраться с этой сложностью, подробно описав, что следует и чего не следует делать при написании Go-кода в Uber. Эти правила предусматривают поддержку кода в управляемом состоянии, одновременно позволяя разработчикам эффективно использовать возможности языка Go.

Это руководство было изначально создано [Prashant Varanasi] и [Simon Newton] как способ помочь коллегам быстрее освоить Go. С тех пор оно дополнялось и уточнялось на основе отзывов других разработчиков.

  [Prashant Varanasi]: https://github.com/prashantv
  [Simon Newton]: https://github.com/nomis52

В этом документе описаны идиоматические соглашения для Go-кода, которым мы следуем в Uber. Многие из них являются общими рекомендациями для Go, в то время как другие дополняют внешние ресурсы:

1. [Effective Go](https://go.dev/doc/effective_go)
2. [Go Common Mistakes](https://go.dev/wiki/CommonMistakes)
3. [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments)

Мы стремимся к тому, чтобы примеры кода были корректными для двух последних минорных версий [релизов](https://go.dev/doc/devel/release) Go.

Весь код должен выполняться без ошибок при запуске `golint` и `go vet`. Мы рекомендуем настроить ваш редактор так, чтобы:

- Запускать `goimports` при сохранении
- Запускать `golint` и `go vet` для проверки ошибок

Информацию о вспомогательных инструментах Go в редакторах можно найти здесь:
<https://go.dev/wiki/IDEsAndTextEditorPlugins>
